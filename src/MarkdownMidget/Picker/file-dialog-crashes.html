When Windows' Open or Save dialog crashes

A guide for finding which add-on is crashing it, written for Markdown Midget but true for any program on your PC.

What happened

The Open and Save dialog isn't only Windows. Other programs plug small add-ons, called shell extensions, into it: the badges on file icons (a cloud-sync tick, a source-control mark), extra entries in the right-click menu ("Scan with…", "7-Zip"), and file previews and thumbnails. An add-on runs inside whichever program shows the dialog. If it has a bug, it can crash that program, even though the program never asked for it.

Markdown Midget shows the dialog from a separate helper, so only the helper crashed and your document was never at risk. It then switched to its own built-in file picker, which loads no add-ons.

What we can and can't tell

  • We can read what Windows recorded about the crash, and which add-ons are installed.
  • We can't see which add-on was running at the moment of the crash, so the add-ons we list are leads, not proof. The list is of products that other people have reported crashing programs, not products known to be faulty.
  • Markdown Midget never disables, removes or changes anything on your PC. Every step below is yours to take, and each one can be undone.

Reading the clues in the notice

  • What Windows recorded. If it names a file such as DropboxExt64.52.dll, that is the strongest lead: find the program it belongs to. If it names coreclr.dll, ntdll.dll, KERNELBASE.dll or Markdown Midget itself, that is only where the crash was reported, not where it started. If there is no record, the helper may have been closed or ended rather than crashed.
  • The add-ons we list. Start with these: they are installed on your PC, and each has a history of crashing programs that load it.
  • Open this folder in Explorer. Explorer loads the same add-ons, in its own process, so it can't crash Markdown Midget. The badges on the files and the extra entries in their right-click menus show you which add-ons are at work there. If Explorer itself misbehaves in that folder, that is the same problem.

Finding the culprit with ShellExView

ShellExView is a free tool from NirSoft that lists every shell extension and can switch each one off and on again. Download the version that matches your Windows (almost always 64-bit), unzip it, right-click shexview.exe and choose Run as administrator: switching add-ons off needs it.

  1. Choose Options ▸ Hide All Microsoft Extensions, so you only see other programs' add-ons.
  2. Select them all (Ctrl+A) and save the list with File ▸ Save Selected Items, so you know what was on before.
  3. With them all still selected, choose File ▸ Disable Selected Items (F7).
  4. Restart Explorer: Options ▸ Restart Explorer, or sign out and back in.
  5. In Markdown Midget, open Edit ▸ Settings, clear Always use the built-in file picker, and open File ▸ Open… in the same folder as before.
  6. If it works now, one of the disabled add-ons is the culprit. Enable half of them again (File ▸ Enable Selected Items, F8), restart Explorer and try again. If the crash comes back, the culprit is in that half; if not, it's in the other half. Keep halving until one add-on is left.
  7. Enable everything except the culprit, and restart Explorer once more.

Each crash switches Markdown Midget back to the built-in picker and shows the notice again. That's expected while you search: clear the setting again before the next try. If the dialog still crashes with every add-on disabled, a shell extension isn't the cause; please tell us.

Keeping the program, losing the add-on

You rarely need to uninstall anything. Look in the program's own settings for Explorer integration, icon overlays or badges, or the right-click menu. Some that we know of:

  • 7-Zip: in 7-Zip File Manager, Tools ▸ Options ▸ 7-Zip, clear Integrate 7-Zip to shell context menu.
  • TortoiseSVN or TortoiseGit: Settings ▸ Icon Overlays lets you turn the badges off or limit them to the folders you use; Context Menu trims the right-click entries.
  • Adobe Acrobat or Reader: Edit ▸ Preferences ▸ General, clear Enable PDF thumbnail previews in Windows Explorer.
  • NVIDIA: in NVIDIA Control Panel, the Desktop menu, clear Add Desktop Context Menu.
  • Dropbox, and some cloud-sync and antivirus tools: if you can't find a switch for the add-on, ShellExView is the way to turn it off.

An update can bring it back

When a program updates, it can register its add-ons again and switch back on one you disabled. One of the people who make Markdown Midget had another Markdown editor crash in its Open dialog. The cause was a Dropbox add-on: disabling it fixed the crash, until a Dropbox update restored the add-on and the crash came back. If the notice returns after an update, open ShellExView and look again.

Turning Windows' dialog back on

Open Edit ▸ Settings and clear Always use the built-in file picker. If Windows' dialog crashes again, Markdown Midget switches back and tells you, and nothing is lost.

Telling us

In the notice, Copy details copies what it found as plain text: the version, what Windows recorded, and every add-on from outside Microsoft with its file path. The paths can include your Windows user name, so read it before you post it. Paste it into a new issue at github.com/FuncularLabs/MarkdownMidget/issues, with what you tried and what happened. If Markdown Midget itself reported an error, %LocalAppData%\MarkdownMidget\crash.log helps too.
